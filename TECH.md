# Tech Stack — WaterTracker

## Frontend

| Параметр | Значення |
|---|---|
| Фреймворк | React + TypeScript |
| Стан застосунку | React Hooks + Context API |
| Маршрутизація | React Router |
| Стилізація | CSS Modules |
| Збірка | Vite |

**Чому обрали:**

React дозволяє створювати компонентний інтерфейс і розподіляти роботу між учасниками команди. TypeScript допомагає виявляти помилки типів під час розробки. Vite забезпечує швидкий запуск локального середовища та збірку застосунку.

React Hooks і Context API достатньо для початкового керування станом MVP без додаткових складних бібліотек.

CSS Modules дозволяє ізолювати стилі окремих компонентів.

## Backend

| Параметр | Значення |
|---|---|
| Мова | TypeScript (Node.js) |
| Фреймворк | Express |
| База даних | PostgreSQL |
| ORM / драйвер | Prisma |
| Автентифікація | JWT + bcrypt |
| Документація API | Swagger / OpenAPI |

**Чому обрали:**

Node.js та Express дозволяють створити REST API для роботи з користувачами та записами споживання води.

TypeScript забезпечує типізацію серверного коду та спрощує узгодження моделей даних між frontend і backend.

PostgreSQL використовується для надійного зберігання структурованих даних. Prisma спрощує роботу з базою даних, міграціями та моделями.

JWT застосовуватиметься для автентифікації користувачів, bcrypt — для безпечного хешування паролів.

Swagger / OpenAPI дозволить документувати та перевіряти API, а також спростить інтеграцію frontend і backend.

## Інфраструктура

| Параметр | Значення |
|---|---|
| Хостинг frontend | Vercel |
| Хостинг backend | Render |
| Хостинг бази даних | Neon (PostgreSQL) |
| Хмарне файлове сховище | Не потрібне для базового MVP |
| Контроль версій | Git + GitHub |
| Управління завданнями | GitHub Issues + GitHub Projects |
| CI/CD | GitHub Actions (планується) |

**Чому обрали:**

Vercel забезпечує публікацію frontend, Render — розгортання backend, Neon — хмарне зберігання даних PostgreSQL.

Ці сервіси дозволяють представити працюючий MVP через браузер без налаштування власного фізичного сервера.

GitHub використовується як єдине середовище командної розробки, перевірки коду та контролю виконання завдань.

## Командний процес розробки

Використовуємо GitHub Flow.

1. Кожна задача створюється як GitHub Issue.
2. Issue додається до GitHub Projects і призначається відповідальному учаснику.
3. Для виконання задачі створюється окрема гілка `feature/*` або `fix/*`.
4. Зміни передаються через Pull Request.
5. Перед злиттям проводиться Code Review.
6. Для злиття в `main` потрібне щонайменше одне схвалення.
7. Гілка `main` зберігає стабільну версію застосунку.
